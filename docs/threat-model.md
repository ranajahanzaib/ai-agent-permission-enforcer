# Threat model

## Assets and boundaries

Assets are tenant financial data, user identities, agent credentials, delegations, approval evidence, policy configuration, and audit history. Trust boundaries exist between agent and gateway, browser and API, API and database, Cedar and tool execution, and a human approver and approval API.

| Threat                                         | Invariant and enforcement                                                                                     | Evidence                                                    | Remaining limitation                                                                                                                                   |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Agent privilege escalation or prompt injection | Tool allowlist and Cedar decision; prompt text is never identity                                              | `ai-agent-permission-enforcer-core` default-deny tests      | Only a small tool set is implemented                                                                                                                   |
| Cross-tenant read/write                        | Resolve resource tenant in backend and compare before handler                                                 | core and API integration tests                              | Scenario coverage is limited to implemented tools                                                                                                      |
| Identity spoofing/confused deputy              | Hashed credential record maps to fixed agent and tenant; request identity claims are ignored                  | credential lifecycle and gateway scenario integration tests | An operator-configured bootstrap credential requires local secret management; otherwise startup creates a random internal credential for the simulator |
| Approval replay or substitution                | Fingerprint binds canonical payment details and resource version; execution consumes approval transactionally | workflow integration tests                                  | Payment is simulated, not sent to a provider                                                                                                           |
| Expired or revoked delegation use              | Lookup checks expiry/revocation for every call and before execution                                           | API integration tests                                       | User/agent records and session issuance are demo fixtures                                                                                              |
| TOCTOU and duplicate payment                   | Execution rechecks state and writes unique execution with audit in one transaction                            | concurrent workflow integration test                        | SQLite local reference; no distributed payment semantics                                                                                               |
| Policy failure or audit bypass                 | Cedar errors deny; audit failure prevents protected mutation                                                  | API failure-injection test                                  | No tamper-proof audit retention or external sink                                                                                                       |
| Resource guessing/enumeration                  | Foreign resources denied without returned record data                                                         | cross-tenant API scenario                                   | Authentication/session rate limits are not implemented                                                                                                 |

Authorization reduces what the application executes. It does not make model output safe or prevent all prompt injection.
